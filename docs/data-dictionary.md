# Data dictionary

All tables in [`data/`](../data) are derived from the published pivot tables of the Q1 2024 sales
analysis. Each file is regenerated by `python analysis/build_tables.py`, which also asserts that the
totals reconcile.

Common conventions:

- **Currency** — US dollars, unformatted integers unless the column name ends in `_pct`.
- **Percentages** — expressed as percentage points (e.g. `35.22` means 35.22%), not fractions.
- **Rounding** — `revenue_per_unit` and `revenue_share_pct` are rounded to two decimals for display;
  all totals are computed from unrounded source values.

---

## `revenue_by_region.csv`

One row per region, sorted by revenue descending.

| Column | Type | Description |
| --- | --- | --- |
| `region` | text | Sales region: East, North, West, South |
| `revenue` | integer | Total sales value in the region |
| `units_sold` | integer | Units sold in the region |
| `revenue_per_unit` | decimal | `revenue / units_sold`; value intensity of the regional mix |
| `revenue_share_pct` | decimal | `revenue / 112600 × 100` |

## `revenue_by_salesperson.csv`

One row per salesperson, sorted by revenue descending.

| Column | Type | Description |
| --- | --- | --- |
| `salesperson` | text | Salesperson name (5 in scope) |
| `revenue` | integer | Total sales value attributed to the salesperson |
| `units_sold` | integer | Units sold by the salesperson |
| `revenue_per_unit` | decimal | `revenue / units_sold` |
| `revenue_share_pct` | decimal | Share of the $112,600 quarter |

## `units_by_region_and_salesperson.csv`

The coverage matrix: one row per salesperson, one column per region.

| Column | Type | Description |
| --- | --- | --- |
| `salesperson` | text | Salesperson name |
| `East`, `North`, `South`, `West` | integer | Units sold by that salesperson in that region |
| `total_units` | integer | Row total; matches `units_sold` in the salesperson table |

Jane Smith's `North` value is **0** — she recorded no North volume in the quarter. This is a real
zero in the source matrix, not a missing value.

## `revenue_by_product.csv`

One row per product, sorted by revenue descending.

| Column | Type | Description |
| --- | --- | --- |
| `product` | text | Product name (10 in scope) |
| `category` | text | Electronics or Furniture |
| `unit_price` | integer | Average unit price for the product, as provided in the source |
| `units_sold` | integer | Units sold |
| `revenue` | integer | Total sales value; satisfies `units_sold × unit_price = revenue` |
| `revenue_share_pct` | decimal | Share of the $112,600 quarter |

| `units_sold` | integer | Sum of member product units |

| `revenue_share_pct` | decimal | Share of the $112,600 quarter |

## `transactions_sample.csv`

The 26 records visible in the published data extract, preserved to document the record schema. This
is **a sample, not the full dataset** — the quarter contains 50 records.

| Column | Type | Description |
| --- | --- | --- |
| `date` | date | Transaction date, ISO 8601. The source workbook stored Excel serial dates; these are converted (serial 45292 = 2024-01-01) |
| `day` | text | Weekday name |
| `region` | text | Sales region |
| `salesperson` | text | Salesperson name |
| `product` | text | Product name |
| `category` | text | Product category |
| `units_sold` | integer | Units on the line |
| `unit_price` | integer | Price per unit |
| `total_sales` | integer | Line revenue; equals `units_sold × unit_price` on every row |

## Derived metrics used in the report

| Metric | Definition | Rationale |
| --- | --- | --- |
| **Revenue** | Sum of total sales | Primary success metric |
| **Units sold** | Count of units | Volume dimension, needed to interpret revenue |
| **Revenue per unit** | Revenue ÷ units | Separates value creation from volume; distinguishes a premium mix from a high-throughput mix |
| **Revenue share** | Segment revenue ÷ 112,600 | Comparability across cuts of different sizes |
| **Average unit price** | Source-provided mean price per product | Explains why revenue and unit rankings diverge |
